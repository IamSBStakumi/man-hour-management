# Jujutsu LTメモ（4分）

## Jujutsuとは（約1分）

- Git互換の分散バージョン管理システム
  - コマンド名は `jj`
  - Gitリポジトリをバックエンドとして利用可能
  - GitHubや、Gitを使うほかのメンバーとも共存できる
- Gitとは作業モデルがかなり違う
  - ブランチよりも「いま、どのコミットを編集しているか」が中心
  - ワーキングコピー自体が変更可能なコミット
  - 現在のコミットは `@` で表す
  - 基本的に `git add` のようなステージング操作はない
- Gitのブランチに近いものは `bookmark`
  - 名前のないコミットでも作業できる
  - pushなどで必要になったときにbookmarkを付ける

## Gitと比べたメリット（約1分）

- コミット履歴をあとから整理しやすい
  - 過去のコミットを直接編集できる
  - コミットの分割・統合・並べ替えがしやすい
  - 途中のコミットを書き換えると、後続コミットも自動でrebaseされる
- 操作を取り消しやすい
  - rebaseやbookmark移動などの操作履歴も記録される
  - 間違えたら `jj undo` で戻せる
- コンフリクトを状態として保存できる
  - rebaseを中断せず、コンフリクトをあとから解消できる
  - Gitの `rebase --continue` のような操作が不要
- 作業開始前にブランチ名やコミット構成を決めなくてもよい
  - まず実装し、あとから履歴を整える使い方に向いている

## Gitと比べたデメリット（約1分）

- Gitとは考え方が異なるため、最初は現在地をつかみにくい
  - 「どのブランチにいるか」ではなく「どのコミットを編集しているか」
  - `bookmark` とGit branchの違いにも慣れが必要
- コマンドを覚え直す必要がある
  - Gitの知識をそのまま対応させるとかえって混乱することがある
- Gitより利用者・日本語情報が少ない
- IDEやGUIなど周辺ツールはGitのほうが成熟している
- Gitとの併用にも注意が必要
  - 同じリポジトリで両方の履歴操作を混ぜると状態を把握しづらい
  - 普段の操作はJujutsu、Gitは既存ツールとの連携用、など役割を分けるとよさそう
